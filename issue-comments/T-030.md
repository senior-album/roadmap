## 구현 완료 (2026-04-22)

### 추가된 엔드포인트
- `GET /residents/import/template` — UTF-8 BOM 포함 CSV 템플릿 다운로드 (Excel에서 열어도 한글 깨짐 없음)
- `POST /residents/import` — 최대 100명 일괄 등록 (staff 권한 필요)

### CSV 스키마
```
name,birth_date,gender,room_number,medical_notes
홍길동,1940-03-15,M,101호,고혈압
김순자,1945,F,102호,
박철수,,M,,당뇨
```

- `name` 필수
- `birth_date`: `YYYY-MM-DD` / `YYYYMMDD` / `YYYY` 허용, 선택
- `gender`: `M` `F` `남` `여` `남성` `여성` 허용, 선택
- `room_number`, `medical_notes` 선택

### 주민등록번호 뒷자리 방지
`_normalize_birth_date()`에서 `-` 기준 분할 후 뒷부분이 7자리 이상이면 **ValueError로 행 거부**. 응답의 `errors`에 해당 행 기록.

```python
if "-" in s:
    parts = s.split("-")
    if len(parts) == 2 and len(parts[1]) >= 7:
        raise ValueError("주민등록번호 형식은 허용되지 않습니다. 생년월일만 입력하세요.")
```

### 안전 장치
- 파일 크기 1MB 상한
- UTF-8 / UTF-8-BOM / CP949 / EUC-KR 순으로 디코딩 시도
- 행별 오류는 개별 거부, 나머지는 계속 진행 (부분 성공)
- 100명 초과분은 잘라내고 에러 리스트에 명시
- `verify_facility_access`로 다른 시설 데이터 주입 방지 (T-100 경로 순회 방지와 동일 원칙)

### 응답 형식

```json
  "errors": [{"row": 5, "name": "김00", "reason": "주민등록번호 형식은 허용되지 않습니다."}]

```

### 로컬 유닛 테스트
헬퍼 함수(`_normalize_gender`, `_normalize_birth_date`) 스모크 테스트 통과:
- 성별 정규화 (M, 남, 여성 → M/F)
- 생년월일 포맷 3종 파싱
- 주민등록번호 거부 ✓
- 잘못된 날짜 거부 (1940-13-50) ✓
