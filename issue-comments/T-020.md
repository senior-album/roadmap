**A. 동의 단위**
- (A1) 3개 체크박스 각각 — 이용약관 / 개인정보처리방침 / 민감정보(얼굴·건강) — 표준

- 권장: A1 + 마케팅 동의 별도(선택)

**B. 약관 버전 관리**
- (B1) DB에 `ConsentDocument(id, type, version, content, effective_from)` + `UserConsent(user_id, document_id, agreed_at, ip, user_agent)` 2테이블
- (B2) 약관 본문은 `docs/legal/*.md`로 git 관리, DB는 버전 해시만 저장
- 권장: **B1** — 법령상 "동의받은 시점의 약관 원문"을 사본 제출 요구받을 수 있음. git 삭제/rebase 위험 배제해야 함

**C. 재동의 트리거**
- 약관 개정 시 로그인한 보호자에게 모달로 재동의 받기 → 미동의 시 서비스 제한
- 최초 구현에선 **회원가입 시만** 받고, 재동의 플로우는 별도 이슈로 분리 권장

### 제안 스키마 (B1 채택 시)

```sql
CREATE TABLE consent_documents (
  id VARCHAR(36) PRIMARY KEY,
  type VARCHAR(30) NOT NULL,  -- 'terms_guardian', 'privacy', 'sensitive_info', 'marketing'
  version VARCHAR(20) NOT NULL,  -- 'v1.0', 'v1.1', ...
  title VARCHAR(200) NOT NULL,
  content TEXT NOT NULL,         -- 동의 시점의 원문 스냅샷
  effective_from TIMESTAMP NOT NULL,
  is_mandatory BOOLEAN DEFAULT TRUE,
  created_at TIMESTAMP NOT NULL,
  UNIQUE(type, version)
);

CREATE TABLE user_consents (
  id VARCHAR(36) PRIMARY KEY,
  user_id VARCHAR(36) NOT NULL REFERENCES users(id),
  document_id VARCHAR(36) NOT NULL REFERENCES consent_documents(id),
  agreed BOOLEAN NOT NULL,  -- 명시적 거부(선택 항목 체크 안 함)도 기록
  agreed_at TIMESTAMP NOT NULL,
  ip_address VARCHAR(45),
  user_agent TEXT,
  INDEX(user_id, document_id)
);
```
