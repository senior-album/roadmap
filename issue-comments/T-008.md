## 감사 결과 (2026-04-22)

**상태**: ✅ 코드 변경 불필요 — 이미 요구사항 충족

### share_token 엔트로피
`share_token` 생성은 코드베이스 전체에서 1곳뿐이며 이미 `secrets.token_urlsafe(32)` 사용 중.

```python
# app/api/photos.py:882
share_token = secrets.token_urlsafe(32)
```

`secrets.token_urlsafe(32)` → 32바이트 난수 = 43자 URL-safe Base64 → 256비트 엔트로피. 무작위 대입 공격으로 발견 불가능 (IP당 30/분 rate-limit도 걸려 있음 — `photos.py:919`).

### 만료 검증
`get_shared_photo` 엔드포인트에서 `expires_at` 검증이 정상 작동.

```python
# app/api/photos.py:931
if share.expires_at and dt.utcnow() > share.expires_at:
    raise HTTPException(status_code=410, detail="공유 링크가 만료되었습니다.")
```

만료 시 **HTTP 410 Gone**을 반환하는 점도 적절 (404가 아니라 "있었는데 이제 없음" 의도를 명확히 표현).

### 남은 잠재 이슈 (T-011과 연계)
- 모델의 `share_token` 컬럼 크기가 `String(100)` — `secrets.token_urlsafe(32)`는 43자라 충분하지만, 향후 `token_urlsafe(48)` (64자) 등으로 늘릴 여지를 감안해 `String(128)`로 올려두는 것도 고려 가능.
- Presigned URL TTL(1h)과 공유 링크 TTL(72h) 불일치는 **T-011에서 다룸**.

**결론**: T-008은 Close 가능. 추가 조치 없음.
