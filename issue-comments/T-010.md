## 완료 (2026-04-22)

`app/main.py` CORS 미들웨어에서 `allow_methods=["*"]`, `allow_headers=["*"]`를 명시 화이트리스트로 교체.

```python
# app/main.py:123
app.add_middleware(
    CORSMiddleware,
    allow_origins=settings.ALLOWED_ORIGINS,
    allow_credentials=True,
    allow_methods=["GET", "POST", "PUT", "PATCH", "DELETE", "OPTIONS"],
    allow_headers=[
        "Authorization",
        "Content-Type",
        "Accept",
        "Origin",
        "X-Requested-With",
    ],
    expose_headers=["Content-Disposition"],
    max_age=600,
)
```

### 변경 근거
- `allow_methods=["*"]`는 CSRF 방어선 약화 — 필요 method만 열기
- `allow_headers=["*"]`도 동일하게 노출 확대 — 실사용 헤더만 유지
- `expose_headers=["Content-Disposition"]` — 파일 다운로드(CSV 템플릿 등)에서 프론트가 파일명 읽을 수 있게
- `max_age=600` — preflight 캐시 10분으로 CORS 왕복 부담 감소

### 프론트엔드 검증 필요
다음 헤더를 실제 쓰고 있는지 확인:
- `Authorization` — Bearer 토큰(쿠키 기반이 기본이라 거의 미사용, 유지)
- `Content-Type` — multipart/form-data, application/json 모두 커버
- `X-Requested-With` — axios 구버전 호환. 안 쓰면 제거 가능

만약 커스텀 헤더를 추가로 쓰고 있으면(`X-Facility-Id` 등) 리스트에 추가하고 PR 수정하겠습니다.

### 검증 방법
```bash
curl -X OPTIONS -H "Origin: http://localhost:5173" \
     -H "Access-Control-Request-Method: POST" \
     -H "Access-Control-Request-Headers: Authorization, Content-Type" \
     -i http://localhost:8000/photos/upload
```
응답에 `Access-Control-Allow-Methods`에 POST, `Access-Control-Allow-Headers`에 위 2개가 포함되어야 함.
